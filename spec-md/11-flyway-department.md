# 4. Normalization Decision

The Department table should store only data that directly belongs to a Department.

Store:

```text
Department Code
Department Name
Faculty Reference
Active Status
Soft Delete Status
Audit Information
```

Do NOT store:

```text
program_count
course_count
student_count
faculty_name
```

These are derived or related values.

Correct relationship:

```text
Faculty
   1
   │
   │
   N
Department
```

The Department table stores:

```text
faculty_id
```

not:

```text
faculty_name
```

# 6. Table Purpose

The `departments` table stores departments belonging to university Faculties.

```text

DEPT-EE
Electrical Engineering
Faculty of Engineering

DEPT-SE

Marketing

```

# 7. Normalized Table Attributes

| Column | Data Type | Constraint | Description |
|---|---|---|---|
| `id` | BIGINT | PK, Identity | Internal Department ID |
| `department_code` | VARCHAR(30) | UNIQUE, NOT NULL | Department code such as `DEPT-CE` |
| `department_name` | VARCHAR(255) | NOT NULL | Department name |
| `faculty_id` | BIGINT | FK → `faculties.id`, NOT NULL | Faculty that owns the Department |
| `is_active` | BOOLEAN | NOT NULL DEFAULT TRUE | Active/Inactive status |
| `is_deleted` | BOOLEAN | NOT NULL DEFAULT FALSE | Soft-delete flag |
| `created_by` | BIGINT | FK → `app_users.id`, NOT NULL | Admin who created the Department |
| `created_at` | TIMESTAMP | NOT NULL DEFAULT CURRENT_TIMESTAMP | Creation timestamp |
| `updated_by` | BIGINT | FK → `app_users.id`, NULL | Admin who last updated the Department |
| `updated_at` | TIMESTAMP | NULL | Last update timestamp |

# 12. Department Name Uniqueness

Department names should be unique within the same Faculty.

Use:

```sql
UNIQUE (faculty_id, department_name)
```

This means:

```text
Faculty A
    ↓
Department Name X

Faculty B
    ↓
Department Name X
```

can technically exist if business requirements allow it.

But the same Faculty cannot contain duplicate Department names.

Example prohibited:

```text
Faculty of Engineering
├── Computer Engineering
└── Computer Engineering
```

└── student_count

Example:

```text

```

```text

    ↓

```

```text

course_count
student_count
```

must NOT exist in this migration.

# 27. Migration 1 - Create Departments Table

Example filename:

```text
V{next}__create_departments.sql
```

Required SQL:

```sql
CREATE TABLE departments (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,

    department_code VARCHAR(30) NOT NULL,

    department_name VARCHAR(255) NOT NULL,

    faculty_id BIGINT NOT NULL,

    is_active BOOLEAN NOT NULL DEFAULT TRUE,

    is_deleted BOOLEAN NOT NULL DEFAULT FALSE,

    created_by BIGINT NOT NULL,

    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,

    updated_by BIGINT,

    updated_at TIMESTAMP,

    CONSTRAINT uk_departments_department_code
        UNIQUE (department_code),

    CONSTRAINT uk_departments_faculty_department_name
        UNIQUE (faculty_id, department_name),

    CONSTRAINT fk_departments_faculty
        FOREIGN KEY (faculty_id)
        REFERENCES faculties(id),

    CONSTRAINT fk_departments_created_by
        FOREIGN KEY (created_by)
        REFERENCES app_users(id),

    CONSTRAINT fk_departments_updated_by
        FOREIGN KEY (updated_by)
        REFERENCES app_users(id)
);
```

# 28. Migration 1 - Required Indexes

Unique constraints already create indexes for:

```text
department_code

(faculty_id, department_name)
```

Do NOT duplicate those indexes.

Create:

```sql
CREATE INDEX idx_departments_faculty_id
    ON departments(faculty_id);

CREATE INDEX idx_departments_is_active
    ON departments(is_active);

CREATE INDEX idx_departments_is_deleted
    ON departments(is_deleted);

CREATE INDEX idx_departments_created_by
    ON departments(created_by);

CREATE INDEX idx_departments_updated_by
    ON departments(updated_by);
```

Recommended combined index for common list queries:

```sql
CREATE INDEX idx_departments_faculty_active_deleted
    ON departments(faculty_id, is_active, is_deleted);
```

# 30. Migration 2 - Add app_users Department FK

Create a separate migration after the Department table migration.

Example:

```text
V{next+1}__add_app_users_department_foreign_key.sql
```

Required SQL:

```sql
ALTER TABLE app_users
ADD CONSTRAINT fk_app_users_department
FOREIGN KEY (department_id)
REFERENCES departments(id);
```

Do NOT change:

```text
department_id
```

to `NOT NULL`.

It must remain:

```text
NULLABLE
```

because:

- Super Admin may not belong to a Department.
- Some administrative users may not belong to an academic Department.
