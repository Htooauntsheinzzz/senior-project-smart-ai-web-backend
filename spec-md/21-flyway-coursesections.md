## 1. Project

**Smart University Student Assistant App**

This specification defines the normalized Flyway migration for:

```text
Academic Management
    ↓
Course Sections
```

The Course Section feature manages individual class sections of an existing Course.

This migration is based on the current **Create Section** form.

The original UI contains:

```text

Capacity
```

```text

```

must be completely removed.


```text
semesters
```

# 5. Table Purpose

The `course_sections` table represents an individual teaching section of a Course.

Example:

```text
Course:
CS101 - Introduction to Programming

Section:
01

Lecturer:
Asst. Prof. Nittaya Chindakharn

Room:
IT-101

Schedule:
Mon/Wed 08:00-09:30

Semester:
Semester 1

Capacity:
50

Status:
ACTIVE
```

A single Course may have multiple Sections.

Example:

```text
CS101
├── Section 01
├── Section 02
├── Section 03
└── Section 04
```

Relationship:

```text
Course
   1
   │
   │
   N
Course Sections
```

---

# 6. Normalized Table Attributes

Use:

| Column | Data Type | Constraint | Description |
|---|---|---|---|
| `id` | BIGINT | PK, Identity | Internal section ID |
| `course_id` | BIGINT | FK → `courses.id`, NOT NULL | Course |
| `section_number` | VARCHAR(20) | NOT NULL | Section number such as `01` |
| `capacity` | INTEGER | NOT NULL | Maximum number of students |
| `lecture_id` | BIGINT | FK → `lectures.id`, NOT NULL | Assigned lecturer |
| `room` | VARCHAR(100) | NULL | Classroom / room |
| `schedule` | VARCHAR(255) | NULL | Human-readable class schedule |
| `semester_id` | BIGINT | FK → `semesters.id`, NOT NULL | Semester |
| `status` | VARCHAR(30) | NOT NULL DEFAULT `'ACTIVE'` | Section status |
| `is_deleted` | BOOLEAN | NOT NULL DEFAULT FALSE | Soft-delete flag |
| `created_by` | BIGINT | FK → `app_users.id`, NOT NULL | Creator |
| `created_at` | TIMESTAMP | NOT NULL DEFAULT CURRENT_TIMESTAMP | Created time |
| `updated_by` | BIGINT | FK → `app_users.id`, NULL | Last updater |
| `updated_at` | TIMESTAMP | NULL | Last update time |

# 26. Why FULL Must Not Be Stored

The UI shows:

```text
Full
```

for a Section such as:

```text
50 / 50
```

But `FULL` should be derived from:

```text
enrolled_students >= capacity
```

Example:

```text
capacity = 50
enrolled = 50

Derived UI status:
FULL
```

Database status may still be:

```text
ACTIVE
```

Correct model:

```text
Persistent status:
ACTIVE / CLOSED

Derived capacity state:
AVAILABLE / FULL
```

# 39. Required Migration SQL

```sql
CREATE TABLE course_sections (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,

    course_id BIGINT NOT NULL,

    section_number VARCHAR(20) NOT NULL,

    capacity INTEGER NOT NULL,

    lecture_id BIGINT NOT NULL,

    room VARCHAR(100),

    schedule VARCHAR(255),

    semester_id BIGINT NOT NULL,

    status VARCHAR(30) NOT NULL DEFAULT 'ACTIVE',

    is_deleted BOOLEAN NOT NULL DEFAULT FALSE,

    created_by BIGINT NOT NULL,

    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,

    updated_by BIGINT,

    updated_at TIMESTAMP,

    CONSTRAINT uk_course_sections_course_section_semester
        UNIQUE (
            course_id,
            section_number,
            semester_id
        ),

    CONSTRAINT chk_course_sections_capacity
        CHECK (
            capacity > 0
        ),

    CONSTRAINT chk_course_sections_status
        CHECK (
            status IN ('ACTIVE', 'CLOSED')
        ),

    CONSTRAINT fk_course_sections_course
        FOREIGN KEY (course_id)
        REFERENCES courses(id),

    CONSTRAINT fk_course_sections_lecture
        FOREIGN KEY (lecture_id)
        REFERENCES lectures(id),

    CONSTRAINT fk_course_sections_semester
        FOREIGN KEY (semester_id)
        REFERENCES semesters(id),

    CONSTRAINT fk_course_sections_created_by
        FOREIGN KEY (created_by)
        REFERENCES app_users(id),

    CONSTRAINT fk_course_sections_updated_by
        FOREIGN KEY (updated_by)
        REFERENCES app_users(id)
);
```

